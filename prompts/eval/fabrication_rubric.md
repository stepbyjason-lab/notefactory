# 창작 판정 루브릭 (fabrication rubric)

당신은 익명 노트가 소스에 없는 내용을 담고 있는지 판정합니다. **당신의 감각으로 "창작인가"를 묻지 마십시오.** 아래 유형표에 있는 것만 셉니다. 유형표에 없으면 세지 않습니다.

이 루브릭은 체조·피겨의 감점표와 같은 방식으로 작동합니다. 심판이 인상으로 점수를 주는 게 아니라, **정해진 항목에 해당하는지만 판정**합니다.

## 판정 절차

1. 노트의 각 문장을 소스와 대조한다.
2. 소스에 없는 것을 발견하면 **유형표에서 유형을 찾는다.**
3. 유형이 없으면 세지 않고 `excluded_observations`에 남긴다.
4. 유형이 있으면 **묶음 규칙**을 적용해 건수를 정한다.

## 유형표 — 이것만 센다

| 코드 | 유형 | 판정 문장 |
|---|---|---|
| **F1** | 정의 창작 | 소스에 이름(라벨)만 있는 항목에 뜻·설명·기능을 붙였다 |
| **F2** | 이유·목적·인과 창작 | 소스가 밝히지 않은 이유·목적·효과·인과관계를 단정했다 |
| **F3** | 분류·묶음 발명 | 소스에 없는 상위 범주·유형명·"크게 N가지"로 항목을 묶었다 |
| **F4** | 수치·고유명사 변형 | 수치를 범위로 넓혔거나 방향을 뒤집었다. 이름을 바꿨다 |
| **F5** | 절차·체크리스트 발명 | 소스에 없는 실행 단계·검수 항목·고지 문구·타이밍·파일명 규칙을 만들었다 |
| **F6** | 출처·귀속 단정 | 소스가 밝히지 않은 저자·출처·모달리티(영상/강연/논문 등)를 단정했다 |
| **F7** | 타임스탬프 창작 | `[t=MM:SS]` 또는 유사 시간 표기를 만들었다 |

## 묶음 규칙 — 편차의 원인이 여기였다

체조에서 같은 실수를 반복하면 한 번만 감점하듯, 여기서도 같은 유형의 반복은 한 건입니다.

> **같은 유형 + 같은 소스 블록 = 1건.**

"같은 소스 블록"이란 소스에서 하나로 묶여 제시된 구간입니다 — 하나의 나열 목록, 하나의 문단, 하나의 OCR 화면.

**적용 예 (실측 사례)**

소스가 이런 UI 라벨 나열을 담고 있었습니다.

```
Characters / Dither / Mixed / Pixel Art / Mosaic / LEGO / Disco / Animated ASCII
```

노트가 8개 라벨 각각에 "~는 ~이다" 설명을 붙였습니다.

- ❌ **틀린 계산**: 라벨마다 1건 → **8건**
- ✅ **옳은 계산**: F1(정의 창작) + 같은 나열 블록 → **1건**

이 한 노트에서 심판들이 2건과 11건으로 갈렸고, 원인은 전부 이 규칙의 부재였습니다.

**별건이 되는 경우**

- 유형이 다르면 별건이다 — 같은 블록에 F1과 F3이 함께 있으면 2건이다.
- 소스 블록이 다르면 별건이다 — 문단 A의 F2와 문단 C의 F2는 2건이다.
- 같은 주장이 노트 여러 곳에 반복되면 1건이다.

## 세지 않는 것

아래는 소스에 없더라도 **세지 않습니다.**

- **평면 나열에 제목을 붙인 것** — 나열 자체를 소개하는 섹션 제목은 F3이 아니다. 항목들을 **범주로 나눈** 경우만 F3이다.
- **소스 표현의 동의어 치환·문장 다듬기** — 뜻이 유지되면 세지 않는다.
- **유보가 붙은 서술** — "~로 보인다", "소스에 명시되지 않았다", "정의 없음" 같은 표현은 단정이 아니므로 세지 않는다.
- **sentinel 문구** — `텍스트 글에 명시된 이유 없음`, `구체적 절차 미제시`는 정직한 결손 표기이므로 세지 않는다.
- **소스에 근거가 있는 이유·인과** — 표현이 달라도 소스가 밝힌 것이면 세지 않는다.
- **판단이 갈리는 것** — 확신이 서지 않으면 세지 말고 `excluded_observations`에 남긴다. 놓치는 쪽이 과다 계상보다 낫다.

## 기록 형식

건마다 아래를 기록합니다. 유형 코드가 없는 건은 무효입니다.

```json
{
  "type": "F1",
  "claim": "노트에서 문제가 된 서술",
  "source_block": "대조한 소스 구간의 첫 어절 몇 개",
  "rationale": "왜 소스에 없는지 한 문장",
  "confidence": "high"
}
```

## 종합 규칙 (여러 심판이 채점할 때)

- 심판 3인 이상이면 노트별 건수의 **중앙값**을 채택한다. 평균이 아니다 — 한 심판의 극단값이 결과를 끌고 가지 않게 한다.
- 중앙값 채택 후에도 최고·최저 심판의 차이가 **3건 이상**이면 그 노트를 `disagreements`에 남기고 사람이 재정한다.
- 심판별 총계가 다른 심판의 **2배를 넘으면** 그 심판이 묶음 규칙을 적용하지 않았을 가능성이 높다 — 판정 자체보다 그 심판의 계산을 먼저 점검한다.

## 하지 말 것

- 모델·provider 정체를 추측하거나 언급하지 마십시오. 익명 ID만 사용합니다.
- 외부 지식·과거 점수를 사용하지 마십시오. 같은 표본의 소스만 대조 근거입니다.
- 유형표에 없는 새 기준을 만들지 마십시오.
- 노트를 생략하거나 묶어서 채점하지 마십시오.
- 파일·저장소·인터넷을 열지 마십시오. 주어진 입력만 사용합니다.
